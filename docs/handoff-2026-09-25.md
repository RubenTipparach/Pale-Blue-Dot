### Why the ghosting fix on `main` is the other session's

While this session worked, another session landed `cloud-ghosting` on `main`:
it keeps last frame's cloud distances and eye and blends a history texel only
when that texel saw what this frame sees. This session's resolve pass fixed
the same fault in the same march, so they could not both stand; the merge
kept `cloud-ghosting` (measured on its own captures) and laid the haze, the
fallback, the timing spans and the pass-off switches over it. The 3D noise did
not conflict.

The two can be COMBINED: `cloud-ghosting` rejects a history texel across a
silhouette, and the resolve's clip would also hold a texel that passes to the
range this frame shows round it. That is a change of its own (write it up,
measure it); the owner has been asked whether to do it.

## Gotchas

- **The game reads `assets/` from the checkout at run time.** An old exe runs
  the new shaders unless the suite's `assets` field lays the old ones over
  (it restores them after every run).
- **`partition` is a reserved word in WGSL** (naga refuses it).
- **`LOD_FADE skipped`** in the log is expected on the first landing after
  startup and on some fast-flight landings; it means that landing popped
  rather than risk holes.
- **Long heredocs through the Bash tool failed** twice ("unexpected EOF");
  patch scripts written to the scratchpad and run with Python were reliable.
- **The C++ build tools vanished mid-session** (Visual Studio's folders were
  emptied by the installer). If linking fails with `could not open
  'kernel32.lib'`, reinstall them:
  `winget install Microsoft.VisualStudio.2022.BuildTools --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"`.
- **A Remote Control session** (`claude remote-control --name Pale-Blue-Dot`)
  was started in its own window at the owner's request; it shares this
  working tree.
