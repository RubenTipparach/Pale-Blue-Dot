lighting-model: today against new

Apple M4 Max (Metal), release build at b85718f, window 1440 x 900, uncapped (--no-vsync), clock pinned at 10:00, first 10 s of each run thrown away. Three scenarios: clouds (--route scenic), storm (--route scenic --rain 1) and walk (--walk-distance 1000). Each variant ran twice, interleaved (A..F then F..A), with nothing else running and the screen unlocked. All 28 runs were valid. This sitting replaces the stopped first pass in 2026-10-29-lighting-all.

The owner's targets are 120 fps (8.3 ms) at the 95th percentile and never below 60 fps (16.7 ms) at the 99th.

Findings

  • The new model costs about 4.2 ms at p50 in flight and 1.4 ms on foot. Today 15.6 / 15.4 ms (clouds / storm) against new 19.8 / 19.7 ms; on the walk 10.4 against 11.8 ms. The spread between repeats is at most 0.55 ms (today's clouds; 0.2 ms or less everywhere else), so every difference below past that is a result. The owner has accepted the cost and will tune it ("Adding more frame time is not a problem").
  • L8 (reflections) is the one part that costs measurably: 1.6 ms at p50 on both flights (new 19.8 against no-L8 18.2), and most of the tail: p99 54.5 against 47.5 ms. It is the first place to tune.
  • L3 (soft shadows) and L4 + L7 (sun bounce, lamp bake) cost nothing measurable here: within 0.1 ms of new on both flights. The first pass's 0.5 ms each did not repeat; it was a single run with no spread.
  • Our bloom costs 2.0 ms at p50 (21.8 against 19.8 ms on both flights). It stays off by default on a Mac, as built; Settings turns it on.
  • The storm costs no more than the clouds with the new model (19.7 against 19.8 ms): the wet film and the lit rain fog are inside the spread.
  • On foot the tail is no worse. Walk p95 / p99: today 18.7 / 31.9 and 13.2 / 15.6 ms over its two runs, new 14.5 / 15.9 and 17.2 / 19.3 ms. Today's first run carried the sitting's start-up hitches; the medians across runs are within each other's spread.
  • Every scenario misses the owner's budgets (p95 8.3 ms, p99 16.7 ms) with both models; today's model already did on this machine. This sitting measures the change, not the budget.

How this was measured

  • One machine, one sitting. The whole sitting ran slower than 2026-10-28's (today's model 15.6 ms here against 10.5 ms then); compare within this report only.
  • On this Mac the column "GPU clouds" spans more than the cloud passes: it rises 4.2 ms with lighting changes that touch no cloud pass, and falls 1.7 ms with L8 off. Read it as GPU time up to the composite, not as cloud cost. "GPU total" is not reported on Metal.
  • Bevy's own bloom was not in this sitting (the first pass had it at 2.4 ms against our 1.6 ms).
  • The frame graphs are in the HTML page; the CSVs and logs are local (output/perf/2026-10-29-lighting).

Each run starts from a fresh world with the clock pinned at 10:00 and throws away its first 10 s. A cloud run that never found cloud, or a route that never landed, is marked invalid and left out. Traces are binned to 0.1 s: the faint line is each bin's worst frame, the solid line its median. Reproduce with:

python tools/perf_suite.py --scenarios clouds,storm --repeats 2 --out output/perf/2026-10-29-lighting-full --variant "today||PBD_LIGHTING=today" --variant new --variant "no-L3||PBD_SOFT_SHADOWS=0" --variant "no-L8||PBD_REFLECT=0" --variant "no-L4-L7||PBD_BOUNCE=0;PBD_LAMP_BAKE=0" --variant "bloom-lite||PBD_BLOOM=lite"
